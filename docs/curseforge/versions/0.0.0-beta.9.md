<h2>v0.0.0-beta.9 - Drawers accept and dispense items again</h2>

<h3>Fixed</h3>
<ul>
<li><strong>Crash placing 3-slot compacting drawers</strong>: <code>BlockEntityDrawersComp.create(slotCount)</code> and <code>BlockEntityDrawersStandard.create(slotCount)</code> ignored the <code>slotCount</code> argument and always returned the 2-slot <code>BlockEntityType</code> (<code>FRACTIONAL_DRAWERS_2</code> / <code>STANDARD_DRAWERS_1</code>). Placing a <code>compacting_drawers_3</code> (or a 2/4-slot standard drawer) produced a block entity that did not match the block and <code>BlockEntity.validateBlockState</code> threw <code>IllegalStateException</code>. Each factory now picks the correct <code>BlockEntityType</code> for its <code>slotCount</code>.</li>
<li><strong>Drawers would not accept or dispense items</strong>: the interaction layer of <code>BlockDrawers</code> and <code>BlockEntityDrawers</code> was unported (<code>useSlot</code>/<code>useSlotInvertible</code>/<code>putSlot</code>/<code>takeSlot</code> returned <code>PASS</code>, <code>interactPutItemsIntoSlot</code> was empty, <code>takeItemsFromSlot</code> returned empty). Ported from upstream Storage Drawers: insert (right-click = 1, double-click = dump matching inventory), extract (left-click = 1, alt action = full stack), open the upgrade UI with Shift + empty hand, <code>setPlacedBy</code> portable-data read, drops, and detached-drawer pull/return (<code>drawer_puller</code> / detached drawer).</li>
<li><strong>"Stack Limit: 0" &mdash; storage capacity was zero</strong>: the block entities' inner data classes (<code>GroupData</code> / <code>DrawerData</code>) had lost their overrides. <code>StandardDrawerGroup.DrawerData.getStackCapacity()</code> and <code>FractionalDrawerGroup.getStackCapacity()</code> return <code>0</code> in the base class and the block-entity subclasses must supply the real value. Restored: <code>getStackCapacity</code> (<code>getStorageMultiplier() &times; getEffectiveDrawerCapacity()</code>), <code>onItemChanged</code> / <code>onAmountChanged</code> (persistence and client count sync), <code>getWorld</code> on compacting drawers (updates the <code>SLOTS</code> block state), and <code>injectPortableData(group)</code> in both constructors (contents were not being saved). Removed two incorrect <code>getDrawerCapacity()</code> overrides that recursed to <code>0</code>; the parent implementation based on <code>getStorageUnits()</code> is used instead. Added <code>BlockEntityDrawers.syncClientCount</code>.</li>
</ul>

<h3>Technical Changes</h3>
<ul>
<li>1.21 &rarr; 26.2 API adaptations in the ported methods: <code>Level.isClientSide</code> &rarr; <code>isClientSide()</code>, <code>Level.random</code> &rarr; <code>getRandom()</code>, <code>Inventory.selected</code> &rarr; <code>getSelectedSlot()</code>, <code>Player.displayClientMessage(Component, boolean)</code> &rarr; <code>sendSystemMessage(Component)</code>, <code>DataComponents.BLOCK_ENTITY_DATA</code> is now <code>TypedEntityData&lt;&gt;</code> (not <code>CustomData</code>) &rarr; <code>getUnsafe()</code>, inner class <code>ContentProvider</code> instantiated via <code>be.new ContentProvider(...)</code>.</li>
<li><code>Block#onRemove</code> does not exist in 26.2: the method added during the port was removed; DROP-mode content drops and KEEP-mode <code>BLOCK_ENTITY_DATA</code> preservation are left as a TODO to port with <code>BlockEntity#preRemoveSideEffects</code>.</li>
</ul>

<h3>Known Gaps (not yet ported)</h3>
<ul>
<li>Rendering of the stored item on the drawer face (<code>BlockEntityDrawersRenderer</code>) and its client registration.</li>
<li>Drawer Controller logic (<code>BlockEntityController</code>): block scanning and inventory aggregation.</li>
</ul>

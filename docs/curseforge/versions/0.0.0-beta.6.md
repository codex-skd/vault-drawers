<h2>v0.0.0-beta.6 - Fix FerriteCore crash + unbound block access</h2>

<h3>Fixed</h3>
<ul>
<li><strong>FerriteCore crash on startup</strong>: <code>IllegalStateException</code> in <code>BlockMeta.<init></code> caused by <code>IntegerSetProperty</code> returning non-deterministic value order. Fixed by sorting values in <code>getPossibleValues()</code>.</li>
<li><strong>Unbound block access crashes</strong>: <code>NullPointerException: Trying to access unbound value</code> for <code>vault_drawers:keybutton_drawer</code> and <code>vault_drawers:meta_indicator</code>. Fixed by deferring block lookups inside DeferredRegister suppliers for both BlockItems and BlockEntityTypes.</li>
</ul>

<h3>Technical Changes</h3>
<ul>
<li><code>IntegerSetProperty.getPossibleValues()</code> now returns a sorted <code>List<Integer></code> for FerriteCore FastMap compatibility.</li>
<li><code>ModItems.registerBlockLazy()</code> — BlockItems now capture block holders and resolve them lazily when the item supplier executes.</li>
<li><code>ModBlockEntities</code> — BlockEntityType suppliers now resolve valid blocks inside the supplier, after blocks are registered.</li>
</ul>

<blockquote><strong>Note</strong>: These crashes occurred during the RegisterEvent phase when items/block entities tried to access blocks that hadn't been fully registered yet. The fix ensures all block lookups happen after the block registration phase completes.</blockquote>

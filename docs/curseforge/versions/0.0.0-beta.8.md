<h2>v0.0.0-beta.8 - Fix recipe sync disconnect on world join</h2>

<h3>Fixed</h3>
<ul>
<li><strong>Client disconnect on world join (recipe sync)</strong>: all five custom recipe serializers in <code>ModRecipes</code> built their <code>MapCodec</code> with <code>MapCodec.unit(X::new)</code> (a fresh recipe instance on every datapack load) but their <code>StreamCodec</code> with <code>StreamCodec.unit(new X())</code> (a different fixed instance). <code>StreamCodec.unit</code> checks identity on encode, so sending the <code>neoforge:recipe_content</code> payload to the client threw <code>IllegalStateException: Can't encode ...@a, expected ...@b</code> &rarr; <code>EncoderException</code> &rarr; the client was dropped right after joining. Each recipe now uses a single shared singleton instance for both codecs.</li>
<li><strong>Recipe <code>personal_key_cofh</code> dropped with warning</strong>: the recipe referenced the item tag <code>#cofh_core:crafting/locks</code>; when that tag is empty or absent, 26.2 discarded the whole recipe ("can't be placed due to empty ingredients"). It is now wrapped in a <code>neoforge:not</code> + <code>neoforge:tag_empty</code> load condition so it only loads when the tag is populated.</li>
</ul>

<h3>Removed</h3>
<ul>
<li>Empty Java package directories: the dead <code>com/jaquadro/**</code> tree inherited from the original mod's package name, plus <code>client/gui</code>, <code>event</code>, <code>framing</code> and <code>recipe</code> under <code>com/stalkingdragons/minecraft/vaultdrawers/</code>.</li>
</ul>

<h3>Technical Changes</h3>
<ul>
<li><code>ModRecipes</code>: added one <code>private static final</code> singleton per custom recipe (<code>ADD_UPGRADE</code>, <code>KEYRING</code>, <code>REMOTE_GROUP_UPGRADE</code>, <code>DETACHED_UPGRADE</code>, <code>PERSONAL_KEY</code>), passed to both <code>MapCodec.unit(...)</code> and <code>StreamCodec.unit(...)</code>.</li>
<li><code>data/vault_drawers/recipe/personal_key_cofh.json</code>: added <code>neoforge:conditions</code> block.</li>
</ul>
